# JSONデータ契約

v1のJSON仕様・受入基準・検証記録を維持し、後半に 開発時の計画 v2（非公開） の「データ契約 v2」と工程2の加工結果を記録する。Schema・TypeScript型・pipeline・配信JSONは契約v2。既存のv1検証結果と、末尾のv2の受入判定を区別して読む。

## 構造と画面との境界

出力先は `public/data/furusato.json`。ルートは `{ metadata, entities }`。型は `src/data-contract.ts` の `FurusatoData`、Schemaは `schema/furusato.schema.json`（JSON Schema Draft 2020-12）。全プロパティを必須とし、追加プロパティを許可しない。欠測は省略せず `null` にする。

主指標と参考差額は**加工時に計算してJSONに入れる**。Python側でDecimalによる丸めと県集計を一度だけ行い、元セルから式を検算できるようにするため。画面は計算済みの値を検索・表示・並べ替えに使い、億円などの表示用丸めだけを行う。表示桁に丸めた受入額・費用・控除から差額を作り直さない。

団体は `entities` に格納し、6桁の `code` 昇順で出力する。

| フィールド | 型・意味 |
| --- | --- |
| `code` | 6桁文字列。全国地方公共団体コード、チェックディジット込み。例 `010006`、`011002`。一意キー・hash用 |
| `kind` | `prefecture` または `municipality`。控除の税目とランキングの区分を兼ねる |
| `prefName` | 都道府県名。県自身も所属県名を持つ |
| `name` | 団体名。県は県名、市区町村は市区町村名。名前を一意キーにしない |
| `receiptAmountYen` | 受入額、代理受入を含む。円整数またはnull |
| `receiptCount` | 受入件数。非負整数またはnull |
| `proxyReceiptAmountYen` | 他団体への代理受入額。受入額の内数。円整数またはnull |
| `solicitationCostYen` | 募集費用の全体合計。円整数またはnull |
| `residentTaxDeductionYen` | 該当税目の住民税控除額（推計含む）。市区町村＝市町村民税、県＝道府県民税の県内集計。円整数またはnull |
| `primaryBalanceYen` | 主指標＝受入額−住民税控除額。符号付き円整数またはnull |
| `referenceBalanceYen` | 参考差額＝受入額−募集費用合計−住民税控除額。符号付き円整数またはnull |
| `history` | `{ fiscalYear, receiptAmountYen }` の18要素の配列、またはnull。西暦2008～2025年度を一度ずつ昇順に収録 |

金額と件数はJavaScriptで正確に扱える整数（絶対値が `9,007,199,254,740,991` 以下）。元の金額・件数は非負、差額は負も許可する。TypeScriptの `number` だけでは整数・範囲・コード形式を保証できないためSchemaでも検証する。

`kind` から税目が一意に決まるので、税目の重複フィールドや団体別の補填フラグは持たない。ランキングは必ず `kind` ごとに別表にし、nullは計算不能として順位対象から外す（0として比較しない）。

ローカルの `data-pipeline/raw/` の3本だけを数値の入力とする。取得担当Claudeが2026-10-18に以下の総務省URLから取得してそのまま配置したことを本人から確認済み。加工時は再取得せず `SHA256SUMS` と照合する。

| --- | --- | --- |
| `receipts` | `001084989.xlsx` / `Sheet1` | https://www.soumu.go.jp/main_content/001084989.xlsx |

| 入力 | 列 | 出力・処理 |
| --- | --- | --- |
| 受入 | A | `code` |
| 受入 | B / C | `prefName` / 市区町村の `name`。県の `name` はB |
| 受入 | D / E | `receiptCount` / `receiptAmountYen`（件 / 円） |
| 受入 | K | `proxyReceiptAmountYen`（円）。Jは代理受入の件数なので使わない |
| 受入 | R | `solicitationCostYen`（円）。L:Qの費用の全体合計 |
| 控除 | A | 6桁に正規化した市区町村コードで受入と結合 |
| 控除 | BE | 市区町村の `residentTaxDeductionYen`（市町村民税、円、推計値含む） |
| 控除 | BH | 各市区町村の道府県民税（円、推計値含む）。各行を丸めて県へ集計 |
| 推移 | A / B | 都道府県名 / 市区町村名。コードがないため後述の名寄せを行う |
| 推移 | C,E,G,I,K,M,O,Q,S,U,W,Y,AA,AC,AE,AG,AI,AK | 2008～2025年度の受入額（千円）。×1,000して円にする |

受入の **S:Yはポータルサイト運営事業者に支払った費用という内数**。Rに加算したり、Rの代わりに使ったりしない。控除のF/Mなどの別の控除欄や、市町村民税と道府県民税を足した額でBE/BHを置き換えない。指定都市もBE/BHの公表値をそのまま使い、税率比による再配分はしない。

### コード・本文・県行の判定

- 公式コード表は、控除Excel内の `全国地方公共団体コード` シート（A＝コード、B＝県名、C＝市区町村名）を使う。追加の外部コード表は不要。
- 控除の集計表ではコードが数値で格納されている（札幌市A19は `11002`）。整数の5～6桁を文字列化し左0埋めして `011002` とする。小数や未知コードはエラー。受入側・コード表側も最終的に6桁文字列に統一する。
- 県コードは先頭2桁が県番号、続く3桁が `000`、末尾がチェックディジットという構造を公式コード表と照合して確定する。単なる末尾 `000` 判定ではない。県47・市区町村1,741を明示的に分類する。
- **受入のC列が空かどうかで県を判定しない。** 北海道行のC14は文字列 `0`。他の県行にも同じ形式がある。県の名前に `0` を採用しない。
- Excel XMLの共有文字列・inline文字列は本文の `t` / `r/t` を順番に連結する。ふりがなの `rPh` 以下の `t` は含めない。無差別な全子孫の文字列連結は避ける。
- 結合にはcodeを使い、都道府県・団体名も公式コード表と突き合わせる。名前の一致だけで本体データを結合しない。
- 控除の集計表にはコードのない「北海道集計」など47県の集計行と「総計」行がある。公式コード表の県名＋「集計」または「総計」と一致し、A/Cが空の48行を明示的に除外する。県の控除にはこれらの丸め前集計値を使わず、市区町村BHを行別に丸めた値を足す。それ以外のコード欠落行に金額があればエラーとする。

## 丸め・欠測・指標

1. 元セルの数値文字列から `Decimal` を作る。binary floatを経由させず、`Decimal(float)` やPython組込みの `round` は使わない。
2. 受入のD/E/Kは既に件・円の整数であり、整数であることを検査する。**Rには実際に17団体の小数値があるため、RもDecimalで各行を円単位の `ROUND_HALF_UP` にする。** 契約策定時の「Rは既に整数」という前提を元セルに基づいて訂正した。元値と丸め後の全17件を `data-pipeline/validation.json` の `fractionalCosts` に残す。Schema・型・指標の式は変更しない。
3. 控除BE/BHはそれぞれ**各市区町村行で** `quantize(Decimal("1"), rounding=ROUND_HALF_UP)` して円整数にする。0.5円は1円。Excelに保存された小数の桁を先に削らない。
4. 県の控除＝その県の市区町村の**丸め済みBH**の合計。県の受入額は県自身のE、募集費用は県自身のRを使う。県内市区町村のE/Rを足さない。BHを合計してから丸める方法や、BEを県へ足す方法は不採用。
5. 推移はDecimalで千円値×1,000を行い、円単位で `ROUND_HALF_UP` する。例えば千円値に `4090638.7880000002` のような保存上の端数があっても円へ正規化する。2025年度（AK）は対応する受入Eと円単位で完全一致させる。不一致をEで上書きしない。
6. 主指標＝ `receiptAmountYen - residentTaxDeductionYen`。参考差額＝ `receiptAmountYen - solicitationCostYen - residentTaxDeductionYen`。円整数同士で計算し、結果を再度丸めない。

空セル・空文字は欠測のnull、数値0・文字列 `"0"` は値の0。その他の記号は元表で欠測と確認したものだけnullにし、その記号と根拠を後続の取込記録に残す。未知文字・読取失敗を欠測扱いにして通さない。

式に必要な値が1つでもnullなら、その指標をnullにする。費用だけがnullの場合、主指標は計算できるが参考差額はnull。代理受入額がnullでも、Eと控除があれば両指標を計算できる（代理受入額は式に使わない）。県内BHに欠測または結合欠落があれば県の控除を部分合計せずnullにし、検証時に一覧化する。結合の欠落自体は受入未達とする。

### 推移の名寄せ

キーは `(kind, prefName, name)`。県はAの県名から公式コード表の県を確定し、市区町村はA/Bから突き合わせる。県行・市区町村行・「合計」「全国合計」を区別し、集計行を団体として入れない。

前後の空白・改行の除去以外のあいまい一致は行わない。同じ県で同名の市区町村がある場合は一意に結べないため、該当団体の `history` をnullにする。合併・名称変更などで現行団体との対応が一意に確認できない場合もnullとし、複数団体の推移を足したり同名先へ割り当てたりしない。欠落・余剰・曖昧なキーは一覧化する。

名寄せが一意にできた団体は18年度の配列にする。年度別の欠測はその点の `receiptAmountYen` をnullにし、補間しない。全年度が欠測の場合は配列全体をnullにする。画面は配列全体のnullを「推移なし」と表示し、年度別nullでは折れ線を途切れさせる。

## 後続データ加工の受入基準

Schemaは形・型・範囲を検査する。式・税目・一意性・集計対象・出典との対応はSchemaだけでは証明できないため、以下を加工側の検証で満たす。これは工程①で実データ検証が完了したという意味ではない。

### 全団体・代表値

- 受入は1,788コード＝県47＋市区町村1,741。控除は正規化後1,741市区町村コード。控除に県の直接行がないことは仕様であり、市区町村について結合の欠落・余剰・重複が0であることを一覧と件数で確認する。県は全市区町村のBHを過不足なく一度ずつ県へ割り当てる。
- `entities.code` の一意性、公式コード表との所属・名称・kindの一致、`name === prefName`（県）を検証する。
- 受入のE/K/R・件数・控除BE/BH・推移の単位と税目を元見出しで確認し、S:Yを費用に使わないことを確認する。
- 県控除のJSON合計＝市区町村BHを行ごとに丸めた合計。市区町村控除のJSON合計＝BEを行ごとに丸めた合計。BEとBHをそれぞれ別に、丸め前のDecimal合計と比べ、差の絶対値が `1,741 × 0.5 = 870.5円` 以内であること。
- 対応が一意な推移は2025年度と受入Eの完全一致を検査する。突き合わない推移はnullとし、対象・理由・件数を記録する。2025年度が欠測なら一致確認未了を報告し、検証済みとして数えない。
- 代表の元セル検算：世田谷区 `131121`（受入E665＝797,244,869、R665＝290,266,013）、泉佐野市 `272132`（E1166＝23,038,604,299、R1166＝10,859,274,841）。控除は別行なのでコードで対応を確かめる（世田谷区BE669/BH669、泉佐野市BE1170/BH1170）。
- 先頭0と県の代表は北海道 `010006`（受入E14＝1,990,433,199、R14＝910,469,829）。北海道の控除を県内BHの丸め済み合計から独立検算する。指定都市・先頭0の代表は札幌市 `011002`（受入E15＝4,090,638,788、R15＝1,948,772,045、控除BE19/BH19）。
- nullの伝播・0・負の差額・同県同名・代理受入が正・億円表示後に差額を計算しないことをテストする。全金額と計算結果が安全な整数であることも検査する。
- JSON Schema検証を `format` 検査有効で通す。実JSONの型構造を本TypeScript型と一致させる。

### 全国照合

1. 総務省の**報道資料の全国合計**を別の照合先とする。受入は県47＋市区町村1,741のE合計、控除は市区町村BE合計＋県に集計したBH合計。BHは県側に一度だけ数え、県集計と元市区町村のBHを重ねて足さない。資料が税目別を掲載していればBE/BHを別々にも照合する。
2. 資料側の年度・税目・対象団体・推計の扱い・代理受入を含むかを確認する。代理受入を除く資料ならE合計からK合計を引いた値で照合する。調整は照合上だけで行い、JSONの受入額や指標の定義は変えない。
3. 資料の表示単位と丸め方法を確認して同じ方法で表示桁をそろえ、表示値を一致させる。例えば1億円単位の四捨五入なら表示幅の半分は5,000万円だが、この許容差を単位・丸めの未確認な資料へ流用しない。切捨てなら対応する片側の区間で判断する。
4. 丸め前控除との比較には上記BE/BH各870.5円の丸め誤差上限を使う。代理受入などの既知調整は実額と根拠を記録し、不明差を許容差に含めない。
5. 後続工程でこの節に、資料URL・ページ/表・資料の値と単位・税目/対象範囲・E/K/BE/BHの元合計とJSON合計・調整式・丸め方法・許容差・最終差・合否を記録する。根拠で差を説明でき、宣言した許容差内なら合格。

推移Excelの全国合計（AK1887）との比較も補助検算に使えるが、同系列のExcel内集計なので報道資料との照合を代替しない。資料が取得できない、原因不明のまま一致しない、欠測で必要な合計を確定できない場合は**受入未達**として本人へ報告し、データ検証を緑と呼ばない。

アプリ全体のbuild・TSテスト・Claudeによるブラウザ実操作・見た目の本人選択は 開発時の計画（非公開） の後続の門に従う。今回のデータ加工・Pythonテストの結果とは区別する。

### 計算と画面表示の境界

- 人口比・平均・割合は画面のTS共通関数で計算する。人口・BC・受入額などの分母が0またはnull、あるいは必要な分子がnullなら結果はnull。順位は表示用に丸める前の値を使い、v2の人口比などの並べ替えではnullを末尾に置く。既存の差額ランキングのnull扱いは変えない。
- 県のカードの人口比は「県自身の値÷県人口」と明示する。全国地図は「県内合計（県＋市区町村）÷県人口」。県人口を市区町村の数だけ重複加算しない。
- `deductionUserCount` は「ふるさと納税の控除を受けた住民 ○人」、平均は `deductionDonationAmountYen / deductionUserCount`。寄附先を区別する人数ではないため「ほかの自治体へ寄附した人数」とは書かない。控除を利用していない寄附者は含まない旨を添える。
- 費用の横棒はL:Q、別の段にYとS:Xを「うちポータル事業者への支払額」と表示する。内数を積み上げて二重計上したり「手数料」と断定したりしない。R7実績にR8以降の基準の閾値を当てない。

### v2の後続データ加工の受入基準

以下は合意計画・原票調査に基づく**次工程の門**で、工程1でv2 pipelineの検証を実行済みという意味ではない。v1の全受入基準と検算を維持したうえで追加する。

1. 人口：全1,788団体が結び付き、欠落0・重複0。各コードの県名・団体名・人口列・総計の時点を確認し、**47県すべてで県人口＝所属市区町村人口の和**。行政区・全国計の二重計上を0とする。
2. 普通交付税：上記4件の字体差だけで結合し、対象市町村1,718（交付1,632・不交付86）、県47（交付46・不交付1）、特別区23がそれぞれ一度だけ入る。**交付1,678／不交付87／都と合算23／不明0**、合計1,788。不交付87＝東京都＋86市町村が大綱と一致する。結合欠落・余剰・重複・未知名を一覧化し、不明が出たら受入未達として報告する。
3. 費用：ポータル各項目が対応する募集費用以下であることを全団体で確認し、S:Xの6項目の和がYに一致する。費用は行別・項目別に円丸めする。L:Qの和とRの差は次の3団体の+1円だけを許容し、他は0円。差を吸収するためにRや内訳を変えず、カード付近に「項目ごとの円単位の丸めにより、内訳の合計と総額が1円異なる場合があります」と注記する。

   | code・団体 | 元の合計セル | L:Qの円丸め後の和 | 元Rを円丸めした値 | 内訳の和−R |
   | --- | --- | ---: | ---: | ---: |
   | `222151` 御殿場市 | R998 | 1,030,118,665円 | 1,030,118,664円 | +1円 |
   | `272141` 富田林市 | R1167 | 91,311,266円 | 91,311,265円 | +1円 |
   | `303411` かつらぎ町 | R1289 | 208,939,967円 | 208,939,966円 | +1円 |

   元セルが空の内訳項目はnullのまま残す。欠測を含む和・大小比較は検算不能として対象を一覧化し、欠測を0に変えて「全件一致」としない。今回の原票確認でも空欄があるため、その意味・根拠を確認しないまま次工程の費用検証を緑と呼ばない。上表は値が揃う3団体の元セルと丸めを確認した結果である。

4. 人数・寄附金額：市区町村1,741団体の**BC全国合計が11,514,115人**で、v1報道資料の印字p.9「合計」の控除適用者数と一致する。県のBCはその県の市区町村BCの和、県のBDも同じくBDの和。全国合計には県集計を再度足さず、BF/BGも足さない。各県の集計・BDとBCの対応を検算する。BCが0/null、BDがnullの平均はnullとするテストを追加する。
5. v2構造：Schema v2で追加全項目の存在、4状態、内訳6項目、整数範囲、null、出典6本・単位・時点を検証する。v1 JSONやキー省略を合格にしない。実JSONの `schemaVersion` は2で、型とSchemaの構造が一致し、v1の全件突き合わせ・Pythonテスト・報道資料照合も維持する。
